# 6. 证据核验与生成

> 召回之后，系统先判断"证据够不够"，再决定"怎么答"。本章讲核验、三种生成模式、引用绑定、上下文分层与防幻觉。

## 1. 三种生成模式

| 模式 | 触发条件 | 输入结构 | 输出风格 |
|---|---|---|---|
| `extractive` | `is_framework = False` | 证据 + 上下文 | 逐点引用，先分析后举例 |
| `synthesis` | `is_framework = True` | 证据 + 图谱 + 目录框架 | 先概念骨架，再证据支撑 |
| `chart` | `intent == "chart_analysis"` | 结构化读图 + 证据 | 先图上可读位清单，再建议关注位，最后资料依据 |

**为什么区分**：框架类问题（"市场周期如何转换"）如果按"逐条引用"回答，会变成证据清单；反之，定义类问题用归纳模式容易过度发挥。路由的 `is_framework` 决定前两种；图表问题不看 `is_framework`，`intent` 单独决定 `chart`（`paknow/workflows/graph.py:194-201`）。

### 1.1 chart 模式：结构化读图，而不是让模型再看一遍图

读图的完整设计（字段、截点、失败降级）单独成章：[结构化读图](chapter13-chart.md)。这里只记它在生成侧的三条硬约束：

- **读是类型化的**：`read_chart()` 一次视觉调用把截图读成 `ChartRead` 结构（`paknow/chart.py`），生成阶段消费的是这些字段，不是原始像素的自由发挥；
- **读不可引用**：图上事实由前置读图给出，第一层"可读位"以「图:」开头、不得挂 `[n]`；`[n]` 只允许出现在第三层"资料依据"（`paknow/workflows/generate.py:37-49`，与 ADR-0002 同一条原则：派生观察不进引用集）；
- **答案是照抄不是归纳**：可读位在提示词里已经编号，要求"逐条全列，条数必须与给定条数完全一致"，看不清就写"看不清"，不推算、不补全、不合并（`paknow/workflows/generate.py:129-163`）。

**为什么单独成一个模式**：`extractive`/`synthesis` 的问题是"资料里怎么说"，`chart` 的问题是"这张图上有什么"。前者答案的价值在引用，后者答案的价值在读数；混在一条提示词里，模型会拿书上的形态描述替代图上的真实价位。

## 2. 证据核验与有界补检索

生成前，一次结构化调用判断证据是否充分：

```text
Sufficiency {
  sufficient: bool,
  missing: [..],          # 缺失的条件/证据
  conflicting: [..],      # 冲突来源
  next_query: str | null, # 明确的补检索问句
  reason: str
}
```

规则：

- **零命中** → 直接判不足，触发补检索；
- **达到轮次上限** → 判充分（用现有证据回答），避免无限循环；轮次上限不是硬编码常量，而是路由计划里的 `QueryPlan.max_search_rounds`（默认 3，`paknow/workflows/router.py:48`），由 `paknow/workflows/graph.py:81` 写入运行状态、核验与出边判断各自读取；
- **核验器本身失败** → fail-open（按现有证据回答），而不是报错；
- 补检索的新问句优先级最高（见第 5 章），且证据**跨轮累积**。

**为什么不设固定轮数**：固定轮数要么浪费（简单问题也跑满），要么在复杂问题上不够。有界（`QueryPlan.max_search_rounds` 默认 3）+ 明确缺口才补，是成本与效果的折中。

## 3. 引用绑定

`[n]` 是**证据列表的下标**，不是图号或页码：

```text
[n] → evidence_id → 《书名》→ 章节 → 图号 → PDF 页/印刷页
```

实现细节：

- 生成模型返回 `cited_indices`（0-based 整数）；
- 后端用 `evidence[i].evidence_id` 映射，越界索引直接丢弃；
- 查看器用 `resolve_citations` 渲染成可点击出处。

**为什么不让模型直接输出 evidence_id**：长哈希/ID 容易抄错，且模型对数字下标更稳定；越界校验也更容易。

## 4. 上下文分层：什么能引用，什么不能

| 上下文块 | 位置 | 可引用 | 理由 |
|---|---|---|---|
| 目录框架 | 提示词前部 | ❌ | 只用于定位知识范围 |
| 知识图谱（概念/主张/周期链） | 前部 | ❌ | 派生结构，用于校验与归纳 |
| 图内 K 线指代（BarRef） | 前部 | ❌ | 结构化标注，用于定位 |
| **图读辅助（视觉观察）** | 前部 | ❌ | 派生材料，仅帮助理解形态 |
| 证据列表 | 主体 | ✅ `[n]` | 唯一可引用来源 |
| SOP 降级要求 | 前部 | — | 证据不足时的处理要求 |

**为什么把观察单元移出证据列表**：这样引用编号的语义是干净的——所有 `[n]` 都指向可核验的文本来源。观察文本仍然参与"理解"，但不会出现在引用里。

## 5. 分析优先与图例策略

### 5.1 默认分析

- 答案主体：定义、成立条件、判断逻辑、机制、与相似形态的区别；
- 禁止把图例清单作为答案主体；
- 图读辅助"不引用、不罗列"。

### 5.2 只有明确要例子才给图

当 `wants_examples=True`：

1. 检索阶段做 caption 定向召回，构建**图例目录**（真实 `figure_id` + 图号）；
2. 提示词给出目录，声明"只能从这里选，没有合适的就返回空，禁止编造"；
3. 答案返回 `figure_ids`；
4. 接口只返回**答案实际选中的图**。

实测行为：

| 问题 | wants_examples | 返回图数 |
|---|---|---|
| 双底多头旗形是什么意思？如何判断？ | false | 0 |
| 给我看双底多头旗形的图例 | true | 2（真实图号） |
| 市场周期通常是如何转换的？ | false | 0 |

> 这套机制修复了此前"模型编造图号字符串 → 全部被过滤 → 图例永远为空"的死循环，同时消除了"检索到就罗列"的倾向。

## 6. 防幻觉的边界

系统在提示词与数据层同时设限：

| 风险 | 措施 |
|---|---|
| 编造页码/图号 | 只能引用 `[n]`，出处由后端渲染 |
| 编造胜率/统计 | 提示词禁止；缺失时明确"资料未说明统计口径" |
| 条件丢失 | 提示词要求保留条件与例外；图谱主张带 `qualifiers` |
| 派生材料冒充原文 | `provenance` 标记 + 图读辅助块 |
| 把"你的归纳"当原文 | 要求区分：资料原文 / 你的归纳 / 当前图可见事实 |

## 7. 真实回答示例

**框架类（synthesis）**

> 问题：市场周期通常是如何转换的？
>
> 答案骨架：状态两极（趋势/震荡）→ 趋势生命周期（脉冲→紧密通道→宽松通道→交易区间→新脉冲）→ 转换判定（尝试—回调检验—成立或失败）→ 三类转换路径（自然衰亡 / 反转 / 区间内失败突破）。

**定义类（extractive）**

> 问题：双底多头旗形是什么意思？如何判断？
>
> 答案：先给原文定义（多头趋势中的回调形成双底结构，两次测试同一低点且守住，随后向上突破）[0]；再区分"双底回调（反转形态）"与"双底多头旗形（持续形态）"[2]；最后给判断要点（低点只需"大致相同"、不必是当日最低、旗形本质是回调）。

**指代类（BarRef）**

> 问题：K线2和K线3构成什么形态？
>
> 答案：命中 10 条结构化指代，模型据此回答并对冲突标注保持谨慎（同一图注同时出现"双底牛旗"与"双顶熊旗"两种标注，指出需要区分口径）。

## 8. 本章小结

- 生成质量的前提是"证据集干净"：可引用与不可引用必须物理分离。
- 核验器的作用是止住"明知不足还硬答"，其失败策略应当是 fail-open。
- 分析优先不是提示词技巧，而是由"证据分层 + 图例目录 + 返回过滤"三者共同保证的。
