# AI 评价

> 本章是一份**AI 自评**：由参与实现的大模型撰写的诚实评估。评测集是项目自带的金题（3 套数据集在 `evals/gold/`、4 个 harness 在 `scripts/`，结果产物随仓库提交在 `.scratch/<feature>/`），没有第三方人工双标；分数是主观判断，但每条结论都尽量绑定可核验的证据（计数、实测输出、代码位置）。请把它当作"第二双眼睛"，而不是验收报告。

## 1. 它是什么 / 不是什么

**是**：一个围绕**可追溯证据**构建的本地资料 RAG 系统，带条件主张图谱、派生视觉索引与可版本化的程序性记忆。

**不是**：

- 不是通用问答机器人（资料之外没有知识）；
- 不是图像检索系统（视觉是"观察文本代理"，不是 image-to-image）；
- 不是交易建议系统（明确拒绝无依据的胜率/预测）；
- 不是已完成验证的系统（有金题与盲评，但没有人工双标、没有回测；回归门槛只覆盖确定性记录）。

## 2. 值得肯定的部分

| 优点 | 证据 |
|---|---|
| **引用可追溯** | 每个 `[n]` 绑定 `evidence_id`，最终渲染到书/章/图/页；越界索引被丢弃 |
| **数据审计扎实** | 实测计数暴露了多项"看起来有、实际没有"：父块悬空 1,670/1,670（旧文档里的 743 已过时）、图注几何候选 2,244 而标签链接只 80 条、`page_visual` 集合为空；邻接 `adjacent_ids` 覆盖率 91,235/91,235 |
| **派生材料边界清晰** | 927 条 `derived_observation`（全量 91,235 中的 1.0%）+ 生成端独立"图读辅助"块，引用体系不被污染 |
| **条件化知识（半接线）** | 1,888 条主张全部带 `context`/`modality` 限定；但扩展与渲染读的是 `conditions`/`exceptions`（库里 0 条），所以条件目前是**透传**而不是**筛选**。排序可复现（seed 序 → `extraction_confidence` 降序 → `claim_id`，`paknow/graph/expansion.py:238-243`）。见第 2 章 §4.2 |
| **记忆有生命周期** | `candidate → replay_validated → shadow → active → superseded/retired` 状态机有合法转移表（`paknow/memory/sop.py:3-25`），git 每次变更可 diff；当前 2 个 SOP 一个 `candidate` 一个 `shadow`，`active` 需要离线回放才升得上去 |
| **失败隔离与降级** | 每条召回路径独立 `try/except`；核验器失败 fail-open；重排失败回退 RRF |
| **分析优先** | `wants_examples` 分流；理解类问题不罗列图例；图例目录禁止编造 |

## 3. 必须承认的短板

评测已经起步——3 套金题（`graph_expansion.json` v1 20 题、`graph_expansion_v2.json` 60 题 / 4 层、`chart_v1.json` 10 题）、4 个 harness（`eval_gold` / `eval_answers` / `eval_judge` / `eval_chart`），盲评带硬约束（不允许覆盖确定性判定）——但这些数字本身就不高，且没有一道自动门。

| 短板 | 影响 | 现状 |
|---|---|---|
| **回归门槛只覆盖一半** | 生产链变差不会自动判退，仍靠人肉看表 | 数据集/旁车/运行记录/本章数字的一致性已由 `tests/test_eval_artifacts.py` 在 CI 里守；检索与生成要在有索引和 key 的机器上才跑得起来 |
| **效果仍是低水位** | "图扩展更好"只是小幅成立 | 覆盖 0.2333（text）vs 0.25（graph），Δ +0.0167（3 胜 / 2 负 / 55 平）；盲评正确性 1.183 vs 1.250（满分 2）；无支撑主张 146 vs 119 条 |
| **图谱扩展收益触顶** | 加宽度不再涨分，只加 token | 宽度消融（v2，123 个期望点）：union 探针 73、text w14 41、graph w14 55（net +14）、graph w20 55（net +13）；60/60 题都撞到 14 条证据上限 |
| **图表评测基本没跑** | chart 链路质量接近未测 | 只跑了 10 题里的 2 题（`limit: 2`），56 个期望位置答对 7 个，miss 0.875 |
| **SOP 8 个操作名里 5 个空转** | 记忆优化只完成一半，候选方法可能无效 | 只有 `expand_terms`（→ 额外查询）与 `check_evidence`（→ 证据要求）真生效；`step_back`、`multi_query`、`hyde`、`expand_figures`、`rerank` 只写 flag 无人读，`hybrid_search` 是空操作，`stop` 写进 `sop_stop` 也无人消费（`paknow/workflows/sop_exec.py:25-37`、`paknow/workflows/graph.py:50-53`） |
| **没有 SOP 对照回放** | 无法按胜/负/平比较候选与基线，`active` 门槛自然通不过 | `record_replay` 至今没有调用者 |
| **延迟与成本没有预算** | 交互体验一般，成本不可控 | 答案评测 120 次运行共 4,866.6 s，平均约 41 s/条；云端生成占大头，并行化未做 |
| **视觉能力有边界** | 不能做图像相似检索；观察文本可能漏细节 | 927 图全部有 `vlm_description`，但只是"文本代理"；已在文档与提示词中标注 |
| **图谱质量不均** | 主张来自图注/标题的 LLM 抽取，置信度未回放验证 | `extraction_confidence` 已留字段 |
| **SQLite 并发写** | 后台优化线程与查询并发时可能抖动 | 未开 WAL |
| **可复现性受限** | 资料有版权不入库；模型缓存依赖本机 GPU | 文档给出完整流程 |
| **缺系统消融** | 拿不到"哪一层在起作用"的完整因果 | Ragas/Phoenix 与 B0–B7 全消融仍是空白 |

## 4. 评分（主观，1–10）

| 维度 | 分数 | 理由 |
|---|---:|---|
| 架构与边界 | 9 | 分工清晰；明确不做什么 |
| 数据审计与溯源 | 9 | 定位字段完整；用计数验证设计（也正因如此，1,670 悬空父块才被看见） |
| 检索工程 | 7 | 多路召回 + 重排 + 降级都在；但宽度消融只把 123 个期望点从 41 拉到 55 |
| 查询构建 | 8 | 单次计划稳定；多轮改写有 fallback；词边界与消歧到位 |
| 多模态 | 7 | 927 图全有观察描述且有边界标注；不是跨模态检索 |
| 生成与引用 | 7 | 引用可靠；但 60 题上平均每题 2.0–2.4 条无支撑主张 |
| 记忆体系 | 6 | 生命周期与 git 版本化强；8 个操作名里 5 个空转，`active` 门槛未通 |
| 工程化 | 7 | 接口/存储可迁移；回归门槛只覆盖确定性记录、无延迟/成本预算、SQLite 未开 WAL |
| 文档 | 8 | 决策有来由、有实测依据；但本站曾整体落后于代码（本次已校正） |
| **效果验证** | **5** | **3 数据集 + 4 harness + 盲评都在；但覆盖 0.23–0.25、盲评正确性 1.18–1.25（满分 2）、图表只跑 2/10 —— 量到了，还很低** |

> 横向平均约 **7.3/10**，综合印象取 **7.0**：作为"可追溯、可审计、且**已开始用数字说话**的领域 RAG 工程样板"是高质量的；作为"已被证明效果最优的系统"仍不成立——差距不在缺评测，而在数字本身和缺一道自动门。

## 5. 如果继续做，最值得的三件事

1. **把回归门槛推到生产链**：`tests/test_eval_artifacts.py` 已经守住数据集↔旁车↔运行记录↔数字的一致性，但检索与生成仍要在有索引和 key 的机器上跑。下一步是给这条链路一台能跑索引的 runner，并把图表评测从 `limit: 2` 补到全量 10 题——现在 miss 0.875 这个数字连采样都算不上。
2. **SOP 回放与空转操作接线**：先给 `record_replay` 找到调用者，让候选 SOP 与基线在同一金题上按胜/负/平跑；同时决定 `step_back`、`multi_query`、`hyde`、`expand_figures`、`rerank` 这五个只写不读的操作是接线还是删掉——只写 flag 无人读的代码不算能力。
3. **延迟与成本预算**：实测约 41 s/条（120 次运行 / 4,866.6 s）。先定预算再优化：路由与核验并行、简单问题跳过重排、生成流式化，把 p50 压到 10 s 量级并记录 token 成本。

## 6. 一句话结论

> 这是一套**知道自己不知道什么、并且已经开始把它们量出来**的 RAG 系统：证据可追溯、派生材料有边界、记忆有版本、失败有记录，评测覆盖 0.2333→0.25、盲评 1.18→1.25 都摆在桌面上；它缺的不是更多功能，而是让这道自动门覆盖生产链。
