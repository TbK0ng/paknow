# 图表读图：结构化 `chart_read` 与图表评测

## Problem Statement

用户在网页端上传一张行情截图，问「这张图上哪些价位是关键位」，得到的是一篇**概念综述**：关键位的定义、成立条件、教科书里通常标什么。图上明明印着 `1 @ 7526.75` 这样的标注，回答里一个具体价位都没有，全都写成「看不清 / 资料未说明」。

三处叠加：

- 生成的系统提示要求「只依据提供的证据回答」，而图只是附件；视觉读取按 ADR-0002 又不许当证据用，于是模型把图当成了不能说的东西。
- `chart_analysis` 意图没有接进生成，图表问题和知识问答走同一套提示词。
- 图谱扩展给图表问题添了十几条概念条目，把答案进一步拉向「概念」。

同时用户自己那张 32 MB 的长截图直接让 `/charts` 返回 500（供应商单张图上限 32 MB），页面只显示一张破卡片。

结果：**唯一能证明系统「看过这张图」的东西——图上的价位——从来没有出现在答案里**，而「可追溯」在这个功能上等于零。

## Solution

上传图先做一次**结构化读图**，再用读图结果去检索，最后合成答案：

1. **阶段一 · 读图**：一次结构化调用产出一份 `chart_read`——品种、周期、市场状态、摆动高低点、图上标注价位（含 `strip` 索引与图上依据）、形态、不确定项。它只读图，看不到任何证据，也不产生引用。
2. **阶段二 · 检索**：用读图得到的市场状态、形态与价位去补检索词，图谱扩展对图表问题关闭（概念条目只会稀释答案）。
3. **阶段三 · 合成**：答案分三层——① 图上可读位全列，每条注明图上依据；② 按资料口径收敛出的 5–8 个「建议关注位」；③ 资料依据（带 `[n]`）与归纳。读图结果永不带引用编号。
4. **结构化产物可见**：`chart_read` 出现在 `/charts` 响应里、页面上以可折叠「读图数据」面板呈现、并随整次运行落进 `output`，供 `/runs/{id}` 审计。
5. **读图失败可降级、可见**：超时或非法结构时退回今天的单阶段图文回答，页面标明「未结构化读图」，而不是静默给出一篇概念综述。
6. **非行情截图明确拒答**：不是行情图就说不是，给可见文字/版式摘要，不编价位。
7. **图表 golden 评测**：独立图表题集，只跑确定性判定，产出漏读率、多读率、漂移率三个数字。

## User Stories

1. As a 上传截图的用户, I want 答案先列出图上真实可见的价位, so that 我确认系统真的看过这张图，而不是在读教科书。
2. As a 上传截图的用户, I want 每个价位都附一句图上依据（箭头方向、标注原文、所在区域）, so that 我能自己回图核对。
3. As a 上传截图的用户, I want 价位按我要求的顺序排（如价格从高到低）, so that 我不用再手动排序。
4. As a 上传截图的用户, I want 全部可读标注位原样列出, so that 收敛建议时不会吃掉图上已有的信息。
5. As a 上传截图的用户, I want 在清单之后得到 5–8 个「建议关注位」及其筛选理由, so that 我知道按资料口径该看哪几个。
6. As a 上传截图的用户, I want 筛选建议遵守固定的优先级（图上标注 > 前高/前低 > ONH/ONL > 区间边缘/平台 > 均线）, so that 两个模型两次回答不会给出互相矛盾的取舍。
7. As a 上传截图的用户, I want 价格冲突时保留更极端的那个并把另一条记进不确定项, so that 取舍不是悄悄发生的。
8. As a 上传截图的用户, I want 看不清的数字写「看不清」而不是补齐, so that 我没有被一个编出来的价位数骗。
9. As a 上传截图的用户, I want 图上没印出的品种、周期、指标参数写成「图上未标注」, so that 推断不会被当成事实。
10. As a 上传截图的用户, I want 均线这类指标只说它存在、不给具体数值, so that 动态参考不会被当成静态关键位。
11. As a 上传截图的用户, I want 图上文字标注（如 `2 @ 7519.75`）保留原样, so that 计数和价位的对应关系不丢。
12. As a 上传截图的用户, I want 答案里明确区分「图上可见」「资料依据」「我的归纳」, so that 我知道哪句能查出处、哪句不能。
13. As a 上传截图的用户, I want 读图内容不带引用编号, so that 我不会以为书上写过这张图的价位（ADR-0002）。
14. As a 上传截图的用户, I want 上传长截图时价位不被整体缩小糊掉, so that 数字仍然可读。
15. As a 上传截图的用户, I want 每个价位能指回它来自哪一条条带, so that 我能在长截图里定位它。
16. As a 上传截图的用户, I want 上传 30 MB 的长截图也能正常分析, so that 我不会收到 500。
17. As a 上传截图的用户, I want 上传非图片文件时得到明确的「不是可读图片」, so that 我知道是文件的问题而不是系统坏了。
18. As a 上传非行情截图的用户, I want 系统直接说「这不是行情图表」并给出可见文字摘要, so that 它不会硬凑一张价位清单。
19. As a 上传截图的用户, I want 非行情截图不触发教科书证据检索, so that 回答不会跑题成概念讲解。
20. As a 上传截图的用户, I want 读图超时或失败时页面明确标注「未结构化读图」, so that 我知道这次回答的可信度低一档。
21. As a 上传截图的用户, I want 降级时仍按图表问题的口径回答, so that 失败不会再退回成概念综述。
22. As a 上传截图的用户, I want 图表问题的总延迟控制在 120 秒内, so that 交互不会被一次读图拖到不可用。
23. As a 上传截图的用户, I want 页面上能把读图数据展开看, so that 我能看到模型到底读到了什么、哪一项它自己标了不确定。
24. As a 上传截图的用户, I want 正文仍是一段能读的解释, so that 我不需要自己拼装结构化字段。
25. As a 维护者, I want 读图结果随运行落库, so that 任何一次回答都能事后回放它读到了什么。
26. As a 维护者, I want 读图结果全量保存（含全部标注位与不确定项）, so that 事后能判断「漏读」发生在哪一步。
27. As a 维护者, I want 图表问题关闭图谱扩展, so that 概念条目不再抢占提示词预算。
28. As a 维护者, I want 图表意图在路由失败时仍然成立（有图就是图表问题）, so that 一次截断不会把图表问题降级成知识问答。
29. As a 维护者, I want 文本知识问答的答案口径完全不变, so that 已合并的 60 题评测仍然可比。
30. As a 维护者, I want 图表题集与 60 题文本集分开存放, so that 冻结口径不被污染。
31. As a 维护者, I want 图表题集只引用图片哈希与相对路径, so that 几十 MB 的截图不会进 git。
32. As a 维护者, I want 缺图时该题记为 skipped 而不是失败, so that 评测不会因为没同步图片就红。
33. As a 评测者, I want 漏读率、多读率、漂移率分开统计, so that 「没读到」和「读错了末位」不会混成一个数。
34. As a 评测者, I want 判定不设数值容差, so that 漂移不会被容差藏进命中率。
35. As a 评测者, I want 判定只跑确定性部分, so that 图表评测不额外花一次盲判的钱。
36. As a 评测者, I want 图表题集自带校验测试, so that 题集的结构不会被悄悄改坏。
37. As a 评测者, I want 读图阶段的调用次数可断言, so that 两阶段不会退化成三次调用或重复读图。
38. As a 评审者, I want 术语「读图 / 图上事实 / 条带」进 GLOSSARY, so that 后续代码、测试名与题集用同一套说法。

## Implementation Decisions

**阶段一：读图**

- 新增一个读图系统提示，只产出结构化 `ChartRead`，不接收证据块，因此结构上不可能产生 `[n]`。它取代今天的单阶段图表提示成为图表问题的第一步；单阶段提示保留，作为降级路径与阶段三的系统提示。
- `ChartRead` 的形状（来自 grilling 决议，`00-decisions.md`）：

  ```python
  class Swing(BaseModel):
      kind: Literal["high", "low"]
      price: float | None        # 任一位不确定 → None，不推算
      strip: int                 # 1..N
      basis: str

  class Level(BaseModel):
      price: float | None
      source: Literal["annotation", "swing", "axis", "unknown"]
      strip: int
      basis: str

  class Focus(BaseModel):
      price: float
      why: str                   # 至少一句，按固定优先级

  class ChartRead(BaseModel):
      instrument: str | None     # 图上未印 = None
      timeframe: str | None
      market_state: Literal["trend_up", "trend_down", "trading_range", "unclear"]
      swings: list[Swing]
      levels: list[Level]        # 全部可读位，不裁剪
      focus: list[Focus]         # 5–8 个
      patterns: list[str]
      annotations: list[str]     # 图上文字原样
      indicators: list[str]      # 参数未知写「参数未知」
      unreadable: list[str]
  ```

- 固定优先级 `图上标注 > 前高/前低 > ONH/ONL > 区间边缘/平台 > 均线` 写进读图提示；数值冲突保留更极端者，另一条进 `unreadable`。
- 没有直接印出的品种、周期、指标参数一律 `None` 并记一条 `unreadable`，不得推断。
- 读图阶段整段受 120 秒总预算约束；超时、非法 JSON 或图片不可读时 `chart_read=None`，回落到单阶段图表提示，并在响应里带上「未结构化读图」标记。

**图片预处理（已发货，本 spec 固化契约）**

- 上传图按高度切成条带，保持原分辨率；极高图按条带数与最大边做一次等比缩小，保证不丢行、不超过供应商单图上限。
- 条带编号通过提示词声明（「共 N 张，从上到下为条带 1..N」），不在像素上烧字。
- 不可读的图片在 API 边界以 400 拒绝，不进入流水线。

**阶段二：检索**

- 图表问题不发起图谱扩展；`graph_stats.enabled` 明确为 false，页面照旧显示「图谱扩展：未启用」。
- 由 `market_state`、`patterns`、`focus` 的价格与 `annotations` 里的术语合成检索子查询；没有可用读图结果时退回当前文本路径。检索子查询的条数与形态沿用现有查询改写器的上限。

**阶段三：合成**

- 图表意图进入生成的方式由「框架/非框架」扩展为三态：读图成功走图表提示，读图失败走单阶段图表提示，其余维持既有分支。
- 图表提示的硬规则：图上事实不得挂引用编号；看不清不推算；用户要清单就只给清单；非行情截图明确说明。
- 生成返回值多一个 `chart_read` 键（成功时为结构化对象，失败时 `None`）。这是它进入运行轨迹的唯一通道——轨迹的 `output` 是 JSON 列，无需迁移。
- `/charts` 响应新增 `chart_read` 字段（字段白名单显式加入）；`/query` 不返回该字段。
- 页面正文仍由模型散文承担；`chart_read` 以可折叠「读图数据」面板呈现（价位表 + 不确定项）。

**评测接缝**

- 图表题集走现有 `run_item → run_query` 边界（`run_query` 本就接收图片列表），不新增接缝；题集条目多一个图片定位字段，加载器按哈希校验，缺图则整题 skipped。
- 图表题集为独立数据集文件，自带校验测试；不复用、不追加 60 题文本集。

## Testing Decisions

**什么算好测试**

只断言缝外的可观察行为：`run_query` 返回的结构与页面/API 拿到的字段、三个率、以及「图表问题与文本问题的提示口径确实不同」这一条不变量。不断言提示词原文（除既有的两条不变量断言），不断言内部函数调用顺序，不复制实现逻辑。

**被测模块与接缝**

- `paknow.workflows.graph.run_query`（最高行为缝）：读图成功时返回 `chart_read`；读图失败时 `chart_read=None` 且回答仍按图表口径；图表问题 `graph_stats.enabled` 为 false；文本问题行为不变。
- `paknow.gateway`：上传预处理——高图切条带后保持宽度、行数无丢失、单图体积在供应商上限内；非图片输入报错。已有单位测试覆盖切条带，本条只补「极端高图不丢行」。
- `apps.api`：`/charts` 返回 `chart_read`；坏图 400；`/query` 不含该字段。
- 评测器：图表题集的结构校验（独立测试），以及 `skipped` 语义（缺图不判失败）。
- 判定器：三个率是纯函数，直接用固定答案/期望集构造用例，覆盖「命中」「漏读」「多读」「末位漂移」四种组合。

**先例**

- 读图/图表提示接线：`tests/test_chart_answer.py`（已有）。
- 图片预处理：`tests/test_gateway_images.py`（已有）。
- 题集结构校验：`tests/test_gold_dataset_v2.py` 的形式，图表集另起一份。
- 图谱关闭的分区行为：`tests/test_graph_expansion.py`。
- 评测器的 images 接缝与记录字段：`tests/test_eval_answers.py`。

**评测口径**

- 10 张图表，每张标注 `expected_levels`、`expected_swings`、`expected_state`。
- 三个独立率：漏读（期望有、答案无）、多读（答案有、期望无）、漂移（同一价位出现但末位不一致）。命中要求整条一致，不设容差。
- 只跑确定性判定，不调用盲判模型。

## Out of Scope

- 更换视觉模型，或为了读数做局部放大/裁剪交互。
- 一次上传多张图。
- `cutoff` 掩码行为（图表回放遮挡）的任何改动。
- 对话追问时的图片复用：`/charts` 仍然是一次请求一张图，追问需要重新上传。
- 图表问题的 `chart_read` 进入 60 题文本评测口径，或改变文本题的判定方式。
- 引入外部编排框架（agent core）。

## Further Notes

- 图表问题的实测延迟：单阶段约 80 秒，加一次读图约 +20 秒；读图阶段的推理 token 开销远高于文本（单次可达 5–6k），这是 120 秒预算的来源。
- 同一张图两次读图已观察到末位漂移（`7499.25/7499.75`、`7489.15/7489.75`），所以评测用三个率而不是单一通过率；漂移率偏高是**要被看见的事实**，不是要调掉的噪声。
- `chart_read` 不可引用这条与 ADR-0002 一致，不新增 ADR：不可引用由 ADR-0002 覆盖，两阶段退化为单阶段的代价只是一个标志位。
- 术语已在 GLOSSARY 固定：读图（`chart_read`）、图上事实、条带（strip）。
- 决议与事实出处见同目录 `00-decisions.md`。
- 已知限制：页面把长截图切成条带后，模型对条带之间的连续性只有提示词级的说明，跨条带的趋势描述仍可能含糊；这是条带方案的固有代价。
