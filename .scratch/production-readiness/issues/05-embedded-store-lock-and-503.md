# 05: 内嵌向量库独占持有与 503

**What to build:** 内嵌向量库同一时刻只允许一个进程持有。第二个获取者立即失败而不是排队等待，并且失败信息说清是谁占着；这份占用原因要能穿透检索层的兜底捕获，让 API 明确回 503 与可读提示（"评测或脚本正在占用存储，请稍后重试"），而不是返回 200 加一屏空命中。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 客户端获取点加进程级独占锁（文件锁与存储目录同层）；第二个持有者立即失败，不阻塞等待。
- [ ] 占用异常携带持锁进程信息，并有专门类型；检索层现有的 `except Exception` 兜底不得把它吞成失败清单后继续返回空答案。
- [ ] API 捕获该异常后返回 503，提示文案说明"评估/脚本正在运行、可稍后重试"，不暴露堆栈。
- [ ] 单进程内重复获取得到同一客户端，不重复构造。
- [ ] 测试用可注入的锁路径模拟第二个持有者，不真的启动第二进程。
- [ ] 外部向量库地址退路仍然可用（设置后不经过这把锁）。
