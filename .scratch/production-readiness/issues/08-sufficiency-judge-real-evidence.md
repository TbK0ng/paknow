# 08: 充分性判定看到真实证据

**What to build:** 充分性判定拿到的是带证据 id 与定位的真实证据，最多 20 条、每条 400 字，而不是被多样性压到 14 条、每条 120 字、只有序号的摘要。这样它才能指出"缺什么"，有界补检索也才真的会启动。判定规模写进运行轨迹，可审计。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 判定输入改为最多 20 条、每条 400 字，含证据 id 与定位；候选池更大时确实取满 20，不受多样性后 14 条的限制。
- [ ] 运行轨迹记录实际送审的条数与字符数，且与真实送入的一致（不是"配置值"）。
- [ ] 轮数上限仍为 3；判定失败仍 fail-open（不阻断回答）。
- [ ] 判定输出契约不变：缺失项 / 冲突项 / 下一步检索。
- [ ] 测试用 40 条命中的场景验证恰好 20 条进提示词、每条截断到 400 字，且不连库、不调模型。
