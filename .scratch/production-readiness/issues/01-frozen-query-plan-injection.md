# 01: 冻结查询注入口与查询溯源

**What to build:** 生产入口接受一份外部注入的查询计划，跳过路由模型但走完其余整条链路（查询装配 6 槽、召回、重排、多样性、图谱扩展、生成、记录）。结果与运行轨迹写明这份计划从哪来（冻结 / 路由）以及最终装配出的查询列表及其哈希，使两次同输入的运行能逐题逐字比较。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 注入计划时路由节点不调用模型；意图、是否综述机制、路由通道、证据需求、SOP 派生态与"路由得到同一份计划"时完全一致。
- [ ] 注入的计划与路由产出的计划走同一条装配路径，因此注入不会让最终查询列表超过 6 槽，也不会出现"注入后比路由多/少几条"。
- [ ] 结果与运行轨迹都带计划来源标记；运行轨迹的请求 JSON 携带来源与查询列表哈希，无需库表迁移。
- [ ] 装配后的查询列表可以从结果里读到（能直接算哈希、能人眼核对），稳定哈希对同一列表恒定。
- [ ] 同一输入两次调用，逐题查询列表相同（确定性契约；用假网关验证，不调云模型）。
- [ ] 不注入计划时行为与今天一致：仍由路由生成计划。
