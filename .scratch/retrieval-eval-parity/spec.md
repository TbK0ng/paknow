# 评测口径与答案级评测

## Problem Statement

维护者要回答「图谱扩展值不值」，现在有两个缺口。

- **召回口径不对等**：评测基线是并集探针（6 条冻结查询各取 top-20 求并集，不重排、不做多样性），线上文本通道是 `6×top-40 → 重排 20 → 召回宽度 14`。上一轮的「净增 0」是拿 120 条候选的并集和生产 14 条比，既不能证明图谱有效，也不能证明无效。召回宽度 14 也从未被单独消融。
- **从未测过答案**：评测只算检索命中，不生成答案，也没有判定器；「图谱块是否真的帮到了回答」没有任何证据。20 道题只覆盖百科与机制两类，例外/失效家族和带条件主张没有专门题；题库太小，分层差异看不出来。

## Solution

1. 评测增加**生产等价基线**（与线上文本通道同构，只关闭图谱扩展），净增益定义为同口径下图谱模式与文本模式的命中差；并集探针保留为上限参照。
2. 题库扩到 60 题（原 20 题原样并入 + 40 道新题），按百科组合式问法、跨书机制链、例外/失效家族、带条件主张四层分层，新数据集成独立版本与哈希。
3. 新增**答案级评测**：每题在独立上下文里跑完整生产链路（图谱开/关两条臂），先做确定性引用约束，再由一个不知道答案来自哪条臂的判定器按「结论正确、条件保留、引用支撑」评分。
4. 图谱证据预算按实测定为 14；召回宽度作为评测变量跑 2×2 消融；生产宽度本 spec 不改。

## User Stories

1. As a 维护者, I want 评测能跑一条与线上文本通道同构的路径, so that 我可以把图谱的贡献和生产行为直接相减。
2. As a 维护者, I want 生产等价基线只关闭图谱扩展、其余参数完全一致, so that 差值只归因于图谱。
3. As a 维护者, I want 并集探针继续保留, so that 「图谱能不能拿到宽召回之外的证据」这个上限问题仍有答案。
4. As a 维护者, I want 净增益按「图谱模式命中 − 文本模式命中」计算, so that 补回自身丢失的证据不再被误读成增益。
5. As a 维护者, I want 净增益逐题可见, so that 一道题的增益不会被另一道题的丢失抵消。
6. As a 评测者, I want 三种召回模式（并集探针 / 生产等价 / 图谱）的产物分开落盘, so that 每个数字都能追到它是相对谁算的。
7. As a 评测者, I want 冻结查询与数据集哈希保持不变, so that 新旧结果可以逐字段比较。
8. As a 评测者, I want 召回宽度作为命令行变量, so that 我不用改代码就能跑消融。
9. As a 评测者, I want 宽度消融固定其他所有变量, so that 宽度的影响可以被单独读出。
10. As a 评测者, I want 2×2 矩阵的四次运行都有记录, so that 我可以判断宽度与图谱是否有交互。
11. As a 维护者, I want 图谱证据预算按实测定为 14, so that 图谱块内的 graph-only 命中从 6 提到 12，且不超过 token 上限。
12. As a 维护者, I want token 上限仍是唯一的安全护栏, so that 更长的证据单元不会把提示词撑爆。
13. As a 维护者, I want 召回主指标是 graph-only 命中数, so that 每道题恒真的截断标记不再冒充信息。
14. As a 评测者, I want 题库扩到 60 题并分层, so that 例外/失效与带条件主张不会被百科题的平均分掩盖。
15. As a 评测者, I want 原有 20 题在新数据集中逐字段不变, so that 上一轮的证伪结论仍可对照。
16. As a 评测者, I want 每道新题锚定到具体证据单元再写问法, so that 题目不是先想问题再凑证据。
17. As a 评测者, I want 期望答案要点与其来源证据绑定, so that 判定器判的是「有没有答到」，不是「像不像」。
18. As a 评测者, I want 新题由一次看不到检索结果的独立核对把关, so that 题目不会偏向已经召回到的东西。
19. As a 评测者, I want 核对不通过的题进残差表而不是硬塞进金标准, so that 题库质量不会被凑数稀释。
20. As a 维护者, I want 答案评测走完整生产链路, so that 召回、补检索、生成一起被测到。
21. As a 维护者, I want 每题一次无状态调用、生成侧看不到期望证据, so that 答案不是照着标准答案写出来的。
22. As a 维护者, I want 图谱开/关两条臂跑同一批题, so that 答案质量的差值只归因于图谱。
23. As a 维护者, I want 答案引用的 id 必须在自己的可引用集合内, so that 幻觉引用能被确定性拦下。
24. As a 维护者, I want 答案不得引用图谱证据, so that 图谱归纳不会被当成作者原话。
25. As a 评测者, I want 判定器不知道答案来自哪条臂, so that 评分不受分组暗示。
26. As a 评测者, I want 硬约束失败直接判负、模型判定只做排序与诊断, so that 确定性错误不会被平均分抹掉。
27. As a 评测者, I want 结果按层聚合且逐题保留, so that 退化能被定位到具体题目。
28. As a 评测者, I want 跑批可续跑、可限量, so that 一次中断不需要从头再花钱。
29. As a 维护者, I want 跑批预算写进 spec, so that 评测不会悄悄变成一张失控的账单。
30. As a 用户, I want 引用编号仍然只指向可引用证据, so that 评测改动不会把图谱归纳混进出处。
31. As a 用户, I want 生产召回宽度在证据不足前不被悄悄改动, so that 大盘行为不会因为一次评测而漂移。
32. As a 评审者, I want 三种召回模式、两条答案臂与复现命令写进参考文档, so that 下一个人不用读代码才知道数字怎么来的。

## Implementation Decisions

**检索缝与生产链路**

- `retrieve_evidence` 增加 `expand_graph: bool = True`。为 `False` 时不发起种子查询、不展开、图谱证据为空且统计明确标记关闭；文本侧与 `True` 时完全一致。
- `run_query` 透传同名开关（默认开），答案评测用它跑两条臂。
- 不复制文本路径；两个模式必须穿过同一个缝。

**召回评测**

- 模式：`baseline`（并集探针，行为与产物不变）、`text`（生产等价基线）、`graph`（图谱回归）。
- `--text-width`（默认 14）传给多样性步骤，三种模式共用。
- 图谱模式同时给出相对并集探针与相对生产等价基线的两组差值；净增益是后者。
- `MAX_EVIDENCE` 8 → 14；`MAX_CONTEXT_TOKENS=1,200` 与 `MAX_EDGES=32` 不变；token 上限是真正的护栏。
- 召回主指标为 graph-only 命中数；截断标记继续输出但不作判据。
- 产物：并集探针文件逐字节不变；新增生产等价基线文件；图谱回归文件内同时记录两种基线差值。
- 宽度消融：`text`/`graph` × `14`/`20` 四次串行运行，结果表写入回归文档。生产默认宽度不变。

**题库 v2**

- 新数据集独立成文件，拥有自己的 SHA-256 sidecar；原 20 题的 `question`、`expanded_queries`、`expected_evidence`、`expected_relations` 在新文件中逐字段不变。
- 60 题分层：百科 20（原 10 + 新 10）、机制 20（原 10 + 新 10）、例外/失效 10、带条件主张 10。类别字段新增对应取值。
- 新题先选证据锚点（分类边、已对齐主张、标题证据），再写问法；问法不得直接复用百科条目标题。
- 每题新增「期望答案要点」：2–5 条断言，每条绑定来源证据；带条件主张的要点必须写明条件与语气。
- 独立核对：只给题面与候选证据文本、不给检索结果，让模型回答「这些证据是否足以回答、缺什么条件」；不通过或分歧进残差表，不进金标准。
- 数据集校验：题数、分层计数、id 唯一、原 20 题不变、每题至少一个期望证据与一个答案要点。

**答案级评测**

- 每题独立调用完整生产链路，题目之间不共享状态；生成侧只看本题检索结果，看不到期望证据与要点。
- 两条臂：图谱开与图谱关，跑同一批题，顺序固定；温度 0，其他参数一致。
- 落盘：逐题答案、引用 id、可引用集合、路由、轮数、失败列表；判定结果逐题记录；可 `--limit`、可 `--resume`，按题目与臂做 checkpoint。
- 确定性硬约束：引用的 id 必须在该答案的可引用集合内；不得出现图谱 id；期望证据覆盖率按题计算。
- 判定器：一次模型调用，输入只有题面、期望要点、答案与引用证据文本，不包含分组信息；输出三段评分（结论正确、条件保留、引用支撑）与不支持断言列表。
- 硬约束失败直接判负；模型评分只用于排序与诊断，不与硬约束合并成单一分数。
- 聚合：按层与按臂给出硬约束通过率、三段评分的分布、逐题差值。

**预算**

- 60 题 × 2 臂，每题链路内 3–6 次模型调用，外加 1 次判定，单次完整跑批约 600–900 次调用。
- 串行执行；单题失败记录后继续；整批可续跑。判定与生成复用同一网关（`deepseek-flash`，temperature 0），不引入第二个供应商。

**文档**

- 参考文档记录三种召回模式、`--text-width`、两条答案臂、判定器契约、复现命令与单进程约束。
- `GLOSSARY.md` 已固化「并集探针」「生产等价基线」「召回宽度」「净增益」。

## Testing Decisions

- **唯一缝**：`retrieve_evidence`。断言 `expand_graph=False` 时图谱证据为空、统计标记关闭、`failures` 为空，且文本命中 id 序列与开启时逐项相同。
- **生产链路透传**：`run_query` 的开关必须到达检索缝；用假的检索/生成替身断言两臂各自只调用一次，不测真实模型。
- **纯函数直测**：净增益、graph-only、引用硬约束（越界 id、图谱 id、覆盖率）、评分聚合、checkpoint 合并，全部接受数据、返回数据；不测打印格式。
- **判定器契约**：断言发给判定的消息里不含臂名、模式或失败列表；判定输出被严格解析，缺字段即失败。
- **数据集校验**：题数、分层计数、原 20 题逐字段不变、id 唯一、每题锚点与要点齐全；哈希 sidecar 校验沿用。
- **好测试的标准**：只断言对使用者可见的结果（命中集合、引用是否合法、评分与聚合），不断言内部调用次数（透传除外）、数据库查询次数或模型措辞。
- **先例**：`tests/test_retrieval_pipeline.py`（缝的分区行为）、`tests/test_eval_gold.py`（评测纯函数与冻结数据）、`tests/test_graph_expansion.py`（网关替身与 `[n]` 绑定）。
- 答案跑批与宽度消融是离线运行，不是 CI 门禁；PR 附结果摘要。
- 判定器上线前人工抽查 10 条答案：判定为通过但引用明显不支撑的，视为判定器缺陷，先修判定再跑全量。

## Out of Scope

- 修改生产召回宽度（消融只产出证据；若 20 胜出，另开生产变更并单独评估提示词增长）。
- 提示词总预算重排、图谱块渲染格式调整。
- 扩大候选池（主张对齐残差、新增关系类型）。
- CI 门禁与全量评测框架（RAG Triad 等）。
- `visual_page` / `numeric` 路由的接线或删除。
- 判定模型的微调或换供应商。

## Further Notes

- 本 spec 基于 `feat/graph-expansion` tip `ce1befd`（PR #1）。若 PR #1 先合并，rebase 到 `main` 并把 **Review base** 更新为合并后的 sha。
- 回归、消融与答案跑批必须串行：embedded Qdrant 单进程，并发会互相锁。
- 实测口径：cap 14 的 20 题运行中，文本命中 9–14 条、图谱块 654–946 tokens、`failures` 0；这些数字在数据集不变时应可复现。
- 生成侧只有一个 DeepSeek 客户端；本地模型只做嵌入/重排/VLM，不能生成答案。判定器是新代码，仓库里此前没有任何 judge 或评分实现。
- CI 目前只跑 scratch 检查与单测，不跑评测。
