# 评测产物入库，并作为数字的唯一来源

`.scratch/<feature>/` 下的运行记录（`summary.json`、逐题 `records.jsonl`、消融 JSON、盲评记录）随仓库提交，而不是 gitignore；数据库（`data/paknow.db`，121.7 MB）仍不入库。理由是：本站与 README 发布的每一个评测数字都必须能被读者逐题核对，否则"我测过"就退化成自述。代价是仓库里多了约 2 MB 的运行记录，且每次重跑都要新增一个目录。

## 考虑过的选项

- **产物全部 gitignore，只留结论**：拒绝。读者无法复核，且两次运行的口径差异（例如 `expected_points` 补齐前后的 `dataset_sha256` 不同）会静默消失。
- **只提交 `summary.json`，丢弃 `records.jsonl`**：拒绝。逐题记录是唯一能回答"这 3 题为什么变好"的材料，也是发现"某次运行用了旧数据集"的依据。
- **把产物转成一份汇总表并提交**：拒绝。汇总表是二手数据，无法复算；且需要额外生成脚本。

## 影响

- **数字有唯一权威**：`book/chapter14-evaluation.md` 是评测数字的唯一出处，其余章节引用它；数字变动先改那里。
- **运行记录带身份**：每个 `summary.json` 记录 `dataset_sha256` 与 `answers_sha256`。引用任何一组数之前先对哈希——目前存在两次全量盲评，分别跑在冻结 v2 与它之前的修订上，`correctness` 的 Δ 方向相反（+0.067 vs −0.05），只有前者可引用。
- **重跑会留下痕迹**：新运行 = 新时间戳目录，不覆盖旧目录；旧的失败口径保留在原地，供复盘。
- **单次判定不当显著**：盲评目前对每个数据集只跑一次，配对胜负（10/6/44）只作方向，不作显著性结论。
