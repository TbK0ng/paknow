# 图谱作为扩展层，而非独立打分召回通道

语料里每条主张都由原文证据支撑（`SUPPORTED_BY` 1,888 条），所以图谱能给出的事实，文本通道原则上召回到的是同一批证据单元；让图谱独立成路、再进 RRF，只会把同一批证据排两遍，既不扩大可选集合，也增加一次遍历延迟。图谱真正独有、文本表达不出的东西只有关系，而现有结构边只有 8 条（`PART_OF` 4、`TRANSITIONS_TO` 4，均为人工种子），其余 `EXCEPTION_TO` / `INVALIDATED_BY` / `CONTRADICTED_BY` / `REQUIRES_CONTEXT` 在数据里为 0。因此决定：图路径不参与打分与融合，只做召回之后的扩展——种子是查询词命中的概念（与文本检索并发）与文本命中里的概念（回填），沿边回取 `evidence_id`，结果与文本证据分区进入 prompt；图谱推出的结论不可直接引用，必须回指底层证据。

## 考虑过的选项

- **独立检索器参与 RRF**：拒绝。召回重叠接近全额，独立打分无法带来文本召不到的候选，只会重复排序。
- **LLM 读三元组做显式推理再回答**：拒绝。结论不可证伪，且与「引用只指向原文」的既有口径冲突。
- **维持现状（图谱只作为 JSON 上下文）**：拒绝。整块序列化进 prompt 浪费预算，且不可回指证据。

## 影响

- **词汇收紧**：`路由` 只指有独立打分的召回；沿边补充叫 `图谱扩展`，不算路由。`QueryPlan.routes` 里的 `graph_local` 需在实现中改名或移出 `routes`，否则词汇与代码分叉。
- **先有边，后有扩展**：增量必须靠 20 条金标准证明（所需证据不在 6 条扩展查询的 top-20 并集内即判定为「图独有」），边没建起来之前不接线。
- **关系复用既有枚举**：标题语法里的「失败」映射为 `INVALIDATED_BY`，不新增 `FAILS_TO`；解析不出的标题直接丢弃，不兜底成 `PART_OF`。
- **引用不变**：图谱结果沿用 ADR-0002 的口径，只能作为理解辅助，出处仍指向原文证据。
